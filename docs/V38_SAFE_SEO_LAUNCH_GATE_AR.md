# GoAcadio V3.8 — Launch gate & SEO release candidate (internal)

**الوضع الحالي: ما قبل الإطلاق. لا ترفع ملفات `docs/seo-release-candidate/` إلى `public/` حاليًا.**

تحديث V3.8 لا ينشر Sitemap ولا يفتح فهرسة Google، ولا يفعّل AdSense. الهدف: مراجعة الروابط والصفحات العامة، وإعداد نسخ مرشحة للاستخدام بعد اعتماد الإطلاق.

## ما الذي تغيّر؟

- صفحة إنشاء الحساب (`/auth`) تعرض روابط واضحة إلى `/privacy` و`/terms` و`/contact`. الشروط الحالية **مسودة توضيحية**؛ لا يوجد مربع موافقة قانونية مضلل على وثيقة غير نهائية.
- `npm run audit:links`: يفحص المسارات المسجلة في `app/routes.ts` ووجود ملفاتها، و**الروابط الداخلية الثابتة** في ملفات TSX/TS، وقائمة sitemap العامة، وبقاء منع الفهرسة. الروابط الديناميكية والمواقع الخارجية تحتاج فحصًا بشريًا.
- `npm run prepare:seo-candidate`: يتحقق من شروط ما قبل الإطلاق ثم يولد `docs/seo-release-candidate/robots.txt` و`docs/seo-release-candidate/sitemap.xml` فقط. لا يغير ملفات الإنتاج أو إعدادات Cloudflare.
- `npm run test:v38`: اختبارات نجاح وفشل مقصود للتأكد من رفض أي تغييرات غير آمنة في الفهرسة/السitemap.

## قبل أي نشر للزوار أو السماح بالفهرسة

1. **المالك/المسؤول**: تحقق من أن البريد `PUBLIC_SUPPORT_EMAIL` حقيقي، وأن رسالة اختبار وصلت إلى صندوق الوارد، وأن فريقًا مسؤولًا يتعامل مع طلبات الخصوصية.
2. **الخصوصية والشروط**: راجع مسودة `/terms` ووصف معالجة البيانات في `/privacy` مع مختص مؤهل، واعتمد نصًا نهائيًا ومعلومات مشغل الخدمة المناسبة. النسخة الحالية **ليست سياسة قانونية نهائية**.
3. **حذف الحساب والبيانات**: اختبر تنفيذ حذف حساب كامل من Supabase Auth مع آثار `on delete cascade` والبيانات المحلية والخدمات المتصلة إن وجدت، من دون استخدام حسابات حقيقية غير مخصصة للاختبار.
4. **اختبار العزل**: جرّب RLS على الأقل بحسابين تجريبيين، بما في ذلك نتائج الاختبارات والمهام والتصدير وحالات الطلبات والإدارة.
5. **Build وتجربة تشغيل**: نفذ `npm ci` (عند توفر lockfile) أو `npm install`، ثم `npm run build` و`npm run typecheck` و`npm run check:live`، واختبر الجوال وGoogle OAuth وتوليد الاختبارات في بيئة تجريبية.
6. **المحتوى**: راجع كل الأدلة وصفحات التعريف وحقوق النصوص، وأصلح أي روابط وأخطاء واضحة. تجنب أي وعود بنتائج امتحانات أو حساب GPA رسمي.
7. **قرار إطلاق صريح**: بعد نجاح كل الخطوات، راجع قائمة الصفحات العامة فقط، وقرّر متى تُزال علامات `noindex` عنها. الصفحات الخاصة والـAPI يجب أن تبقى `noindex` و`no-store`، ومحمية بالمصادقة/RLS؛ الحجب من محركات البحث ليس حاجزًا أمنيًا.

## أوامر فحص النسخة الحالية

```powershell
npm run test:v38
npm run audit:links
npm run check:prelaunch
npm run test:v37
npm run test:v36
npm run check:live
```

تحضير المرشحات داخليًا:

```powershell
npm run prepare:seo-candidate
```

الملفات المقترحة داخل `docs/seo-release-candidate/` وليس `public/`. **لا تعمل Copy أو Deploy لها قبل موافقة إطلاق موثقة.** لا يوجد أمر `publish` تلقائي في هذه النسخة عمدًا.

## عند اعتماد إطلاق الفهرسة في المستقبل (إجراءات مراجعة بشرية)

- راجع قائمة الـ16 URL العامة وتأكد من استجابات HTTP 200 وCanonical لكل صفحة، واستبعد صفحات الحساب والبيانات والـAPI.
- حدّث آلية metadata للصفحات العامة فقط، بحيث تزول `noindex` من أي استجابة عامة يُراد فهرستها. راجع metadata الخاصة بالصفحات والمسارات الرئيسية، وأعد اختبار HTML **المُقدَّم من الخادم** قبل الإطلاق.
- احتفظ بـ`noindex, nofollow` و`Cache-Control: no-store` للصفحات الخاصة؛ استخدم RLS والمصادقة للحماية الحقيقية.
- بعد الاختبارات فقط، انشر نسخة `robots.txt` المعتمدة و`public/sitemap.xml` المُراجَع، وأعد اختبار HTTP وrobots وCanonical و`X-Robots-Tag` ومحتوى HTML.
- **تنبيه:** Google تحتاج الوصول للصفحة لرؤية `noindex`. حظرها في `robots.txt` قد يمنعها من قراءة الوسم؛ لذلك عند الانتقال للفهرسة، راجع السلوك على مستوى الموقع بالكامل وليس تغيير `robots.txt` وحده.
- تحقق من ملكية `goacadio.com` في Search Console عبر DNS، وبعد الإطلاق قدم sitemap وافحص URL Inspection وPage Indexing. تقديم sitemap ليس ضمانًا للفهرسة.
- الإعلانات تُناقَش بعد استيفاء متطلبات AdSense والموافقة عليه؛ لم يُضَف أي كود إعلاني في V3.8.

مراجع رسمية:
- https://developers.google.com/search/docs/crawling-indexing/block-indexing
- https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap

## حدود الفحوص

- الفحوص الثابتة لا تتحقق من الروابط المركّبة ديناميكيًا أثناء التشغيل، ولا من توافر المواقع الخارجية، أو صلاحية RLS الحقيقية أو وصول البريد.
- اختبارات Node المحلية **ليست** بديلًا عن Build أو متصفح أو Audit أمني احترافي.
- لا تضع رموز دخول أو كلمات مرور أو بيانات مستخدمين في تقارير فحص الموقع.
