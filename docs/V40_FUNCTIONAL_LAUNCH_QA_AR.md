# GoAcadio V4.0 — Functional QA / اختبار الوظائف قبل الإطلاق

## 1) ما الذي تم اختباره آليًا؟

- `npm run test:functional` يشغّل **28 فحصًا** على **الوظائف الحقيقية** لملفات التطبيق (وليس إعادة كتابة خوارزميات مشابهة):
  - سلم التقديرات وتحويل النسب إلى درجات والحدود الصفرية والنهائية.
  - تنظيف سياق محادثات AI وتفسير صيغ الإجابة من النموذج.
  - قراءة نتائج الاختبارات المقدّمة من AI، واستبعاد الأسئلة والاختيارات الفاسدة، وحساب الدرجة.
  - تجميع جلسات التركيز، ومهام خطة المذاكرة، وملخص سجل الاختبارات.
  - ترتيب مراجعة المواد حسب الأداء وقلة الأدلة.
  - التحقق من رفض عمليتي AI/Quiz عند غياب تسجيل الدخول وعند وجود Origin مختلف قبل استهلاك أي رصيد.
- `npm run check:live` يفحص استجابات الصفحات العامة، والصفحات الخاصة عند عدم تسجيل الدخول، وrobots وغياب Sitemap المنشور.
- `npm run check:api-guest` يتصل بالموقع المنشور ويرسل **4 طلبات صغيرة بدون أي Authorization** للتحقق من رفض الزائر في المسارين `/api/ai-study` و`/api/generate-quiz` (401 و403). لا يتسبب الفحص في استهلاك AI في الكود الحالي؛ لأنه يتم رفضه قبل خطوة الحصة.
- آخر فحصين **ليسوا ضمن CI المعتاد**؛ لأن Cloudflare قد ينتهي من النشر بعد GitHub Actions. شغّل الفحص الحي يدويًا **بعد اكتمال نشر Cloudflare**.

## 2) الخطوات على GitHub

1. ارفع ملفات ZIP بنفس المسارات إلى `main`.
2. راجع Actions → **GoAcadio build & quality check**؛ يجب أن تنجح فحوص TypeScript وBuild و`test:functional`.
3. تحقق من اكتمال نشر Cloudflare Workers للإصدار نفسه.
4. افتح Actions → **GoAcadio production smoke check** → **Run workflow** → `main` → Run workflow.
5. افتح نتائج الخطوتين؛ نجاحهما يؤكد HTTP/SEO/رفض طلبات الضيوف، **وليس تسجيل الدخول أو جودة AI أو سلامة قاعدة البيانات**.

## 3) قائمة اختبار بشري على الموقع الحي

> استخدم حساب اختبار منفصل عن حسابات الطلاب الحقيقية، وبيانات اختبار غير حساسة. لا ترسل كلمات مرور أو JWT أو مفاتيح API في لقطات الشاشة أو تقارير الأعطال.

| الاختبار | خطوات سريعة | النجاح المتوقع |
|---|---|---|
| 1. التنقل واللغة | افتح الصفحة الرئيسية، بدّل عربي/إنجليزي، انتقل للأدوات | الروابط تعمل والاتجاه صحيح |
| 2. GPA | أدخل مقررين بنقاط 4.0 لساعتين و3.0 لساعة | المتوسط `(4×2 + 3×1) / 3 = 3.6667` تقريبًا؛ العرض يعتمد التقريب |
| 3. Focus Timer | ابدأ جلسة قصيرة ثم أوقف/أكمل حسب الواجهة | الوقت يتغير بشكل صحيح؛ لا يُسجَّل إنجاز غير حقيقي |
| 4. حساب اختبار | أنشئ حساب اختبار ثم سجل الخروج والدخول | استعادة الجلسة من غير أخطاء |
| 5. مواد الدراسة | أضف مقررًا تجريبيًا، ثم أعد فتح Dashboard | يظهر المقرر ولا يظهر بحساب مختلف |
| 6. Planner | أضف مهمة بتاريخ واضح، وعلّمها مكتملة | يظهر الإحصاء الصحيح بعد إعادة التحميل |
| 7. Quiz Generator | بحساب الاختبار جرّب نص محاضرة غير حساس، أو PDF نصّي صغير | تظهر أسئلة صالحة أو رسالة خطأ واضحة؛ قد يستهلك من حصة AI |
| 8. Quiz History | صحح اختبارًا واحفظ النتيجة، ثم افتح سجل الاختبارات | النتيجة محفوظة للطالب الحالي فقط |
| 9. Revision | افتح المراجعة بعد وجود نتائج محفوظة | توصية متناسبة مع عدد المحاولات ونسبتها |
| 10. AI Study | أرسل سؤالًا بسيطًا من حساب الاختبار | إجابة أو رسالة فشل واضحة؛ قد يستهلك من حصة AI |
| 11. Account Export | نزّل JSON بعد تجهيز التصدير | الملف فيه بيانات حساب الاختبار فقط |
| 12. Contact & Privacy | افتح `/contact` و`/privacy` و`/terms` | الرسائل والروابط واضحة؛ بريد الدعم لا يعمل إلا بعد إعداده |
| 13. Mobile | جرّب قائمة الهاتف واللغة وEscape ومفاتيح Tab | لا تداخل أو روابط غير قابلة للوصول |
| 14. الخصوصية | سجّل بحساب اختبار آخر ولاحظ المواد والنتائج | لا تظهر أي بيانات من الحساب الأول |

**مهم:** اختبار فصل الحسابات يدويًا لا يغني عن تدقيق سياسات RLS في Supabase. طلب حذف الحساب إجراء إداري، وليس حذفًا تلقائيًا. لا تستخدم حسابات طلاب حقيقية للاختبار.

## 4) ما الذي لا يثبته V4.0؟

- الـBuild وحده لا يثبت أن ميزات تسجيل الدخول أو قاعدة البيانات أو Workers AI تعمل في الإنتاج.
- الاختبارات الآلية المحلية تعتمد على مدخلات ثابتة ولا تُجري اتصالًا فعليًا بـSupabase ولا تتطلب مفاتيح حقيقية.
- فحص HTTP الحي للضيوف لا يختبر حسابات المستخدمين ولا يحاول إنشاء بيانات أو خصم حصص AI.
- لم نفتح فهرسة Google أو ننشر Sitemap أو نفعّل AdSense.

## 5) لو ظهر فشل

- **Actions: build & quality** أحمر: افتح `Run prelaunch tests, TypeScript check, and production build` وانسخ أول خطأ.
- **Production smoke** أحمر: راجع إن Cloudflare Deploy مكتمل لنفس Commit ثم افتح `Public pages and guest API security`.
- **Feature manual test** فشل: سجّل اسم الصفحة، ما فعلته، النتيجة المتوقعة، نص رسالة الخطأ فقط *بدون بيانات شخصية*، ونوع المتصفح.

لا يتم إرسال بيانات الفحص إلى طرف ثالث بخلاف GitHub Actions نفسه، ولا يحتوي ZIP على أي مفاتيح API أو Cookies أو Secrets.
