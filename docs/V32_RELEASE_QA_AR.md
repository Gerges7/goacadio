# GoAcadio V3.2 — QA and performance checklist

هذا ملف داخلي للمراجعة، **ليس صفحة أو مسارًا عامًا في الموقع**.

## ما الذي تغير؟
- دمج CSS الأساسي وCSS الخاص بـV3.0 وV3.1 في ملف `app/styles.css` واحد. الملفات القديمة موجودة في المستودع، لكنها لم تعد مطلوبة في `<head>`.
- نقل تحميل Google Fonts من `@import` داخل CSS إلى روابط `preconnect` و`stylesheet` في `app/root.tsx`. هذا يقلل سلسلة الطلبات المتعاقبة، لكنه **لا يضمن** تحسنًا محددًا دون القياس.
- قائمة الموبايل: أهداف لمس أكبر، تمرير إذا كانت شاشة صغيرة، Escape للإغلاق مع إعادة التركيز للزر، `aria-expanded`/`aria-controls`، وإشارة للصفحة الحالية.
- رابط «تخطّى إلى المحتوى الرئيسي» للكيبورد، وتحسين `focus-visible`، واحترام إعداد `prefers-reduced-motion`.
- فحص `npm run check:release` (لا يحتاج حزم إضافية) للتحقق من 15 شرطًا ثابتًا.

## طريقة الاختبار بعد نشر Cloudflare
1. افتح `/` و`/guides` و`/tools/gpa-calculator` و`/quiz-generator` و`/dashboard` بالعربي والإنجليزي. راقب Console وNetwork بحثًا عن أخطاء 404 أو hydration.
2. في Chrome DevTools → Network → Disable cache، تأكد أن HTML يحمل ملف CSS محليًا واحدًا، وملف Google Fonts Stylesheet، دون طلب إضافي لملفي `styles-v30.css` و`styles-v31.css`.
3. اختبر على شاشات 320 و375 و768 و1024 بكسل؛ لا يفترض أن تختفي أزرار القائمة أو يظهر تمرير أفقي غير مقصود.
4. على الموبايل افتح القائمة، اضغط Escape بلوحة المفاتيح، وتأكد من رجوع التركيز لزر القائمة؛ افتحها مجددًا وانتقل إلى صفحة داخلية.
5. ابدأ من أعلى الصفحة واضغط Tab: يجب أن يظهر رابط تخطّي المحتوى. اضغط Enter، ثم تابع التصفح بلوحة المفاتيح.
6. فعّل Reduce Motion من إعدادات النظام، وراجع انتقالات الواجهة.
7. راجع تطبيق Focus Timer وCV Builder وطباعة النتائج PDF؛ CSS المدمج يشمل أيضًا قواعد `@media print` السابقة.
8. اختبر بصفحة من القائمة الخاصة بحساب الطالب، وافحص Supabase RLS كما في قائمة V3.0 (التحديث لا يغير الصلاحيات).

## قياسات يجب تسجيلها بعد النشر
- استخدم Chrome Lighthouse في وضع **Mobile** لصفحات `/`, `/tools/gpa-calculator`, `/guides`, `/quiz-generator`، وقارن النتائج قبل/بعد من نفس الجهاز ونفس إعدادات الشبكة.
- الهدف المبدئي: **LCP ≤ 2.5 ثانية، INP ≤ 200ms، CLS ≤ 0.1** عند مستوى 75% من الزيارات الحقيقية. نتائج Lighthouse المعملية وحدها لا تثبت تحقيق أهداف المستخدمين الفعليين.
- افحص حجم CSS المنقول (transfer size) وطلبات Fonts وأخطاء Console وعدد طلبات الشبكة؛ لا تُسجّل تحسنًا بالأرقام قبل قياسه.

## متطلبات ما قبل فهرسة Google والإطلاق العام
- [ ] سياسة خصوصية نهائية ومراجعة قانونية ووسيلة تواصل عامة حقيقية.
- [ ] إجراءات تشغيلية لاستخراج/حذف بيانات المستخدمين، وليس مجرد استقبال الطلبات.
- [ ] اختبار RLS بحسابين مختلفين، وحماية/حدود التكلفة لخدمات AI.
- [ ] مراجعة دقة الأدلة ومحتوى الصفحات العامة.
- [ ] بعد استكمال جميع الشروط، تغيير سياسة `robots.txt` و`noindex` وفق خطة إطلاق مع اختبار Google Search Console، **وليس الآن**.

**ملاحظة مهمة:** `robots.txt` الذي يمنع الزحف و`noindex` كلاهما حاليًا للحفاظ على حالة ما قبل الإطلاق، لكن Google لا يمكنه رؤية `noindex` إذا كان ممنوعًا من الزحف بواسطة robots.txt، لذا منع الزحف ليس ضمانًا لعدم ظهور الرابط في النتائج.

لا تنشر مستندات العمل الداخلية كصفحات عامة، ولا تضف رابطًا لخطة التطوير.
