GoAcadio V3.0 — Account & Privacy Center + Mobile Dashboard
=========================================================

ده تحديث ملفات متغيرة فقط على نسخة V2.9 الموجودة على GitHub main.
خُد نسخة احتياطية من الكود والقاعدة قبل التغيير، ولا تحذف ملفات المشروع الأخرى.

الترتيب:
1) Supabase -> SQL Editor -> New Query. شغّل supabase/007_account_requests.sql بالكامل.
   لازم يظهر: account_requests | true | 3 (عدد السياسات).
   الملف مش بيحذف أو يعدّل بيانات الطلاب الموجودة.
2) GitHub -> Gerges7/goacadio -> main -> Add file / Upload files.
   ارفع الملفات بالمجلدات نفسها app/ وsupabase/ مع الاستبدال.
   ممكن تستخدم زر رفع الملفات أو تسحبهم إلى الريبو مع الحفاظ على المسارات.
3) Cloudflare Deploy: تأكد إن الـBuild نجح.
4) افتح:
   https://goacadio.com/help        مركز المساعدة العام
   https://goacadio.com/account     مركز الحساب والخصوصية (يتطلب تسجيل دخول)
   https://goacadio.com/admin       طلبات الحساب في لوحة الإدارة
   https://goacadio.com/dashboard   اختصارات جديدة أعلى لوحة الطالب
5) اختبار الطلبات:
   - سجّل بحساب طالب وابعث طلب Support.
   - تأكد إنه ظهر في My requests.
   - جرّب إعادة نفس النوع: لازم يمنع تكرار طلب مفتوح.
   - سجّل بحساب الـAdmin وتأكد إنه قادر يشوف ويغير حالة الطلب.
   - سجّل بحساب طالب ثاني وتأكد إنه لا يقدر يشوف طلب الطالب الأول.
   - جرّب طلب حذف حساب وراجع رسالة التأكيد. الحساب يجب أن يظل يعمل بعد إرسال الطلب.
6) افتح الموقع من شاشة صغيرة، جرّب القوائم وGPA والـDashboard والخدمات.

حدود معروفة ومهمة:
- إنشاء طلب حذف حساب لا يحذف الحساب تلقائيًا. التنفيذ مسؤولية الإدارة ويتطلب التحقق من الملكية.
- طلب نسخة بيانات لا ينشئ ZIP أو تقريرًا تلقائيًا.
- رسائل الدعم حاليًا تتطلب حسابًا. لازم توفر بريد دعم حقيقي أو قناة تواصل عامة قبل إطلاق شامل.
- المحتوى الحالي على /privacy معلومات تشغيلية؛ ليس سياسة خصوصية قانونية نهائية.
- Keep noindex until privacy/security/legal review and public-launch checks are complete.
- لا تضع أي service_role secret أو مفاتيح Cloudflare الخاصة في كود المتصفح.

إجراء إداري (للمالك فقط):
1) افتح Admin -> Account & Privacy requests -> اعرف user_id.
2) تحقق من هوية صاحب الطلب باستخدام Supabase Authentication، وما تردش/تبعت بيانات لشخص غير موثَّق.
3) لطلب نسخة بيانات، اجمع بيانات الحساب المعني فقط من الجداول المرتبطة بـuser_id بطريقة آمنة.
4) لطلب حذف حساب، راجع جميع الجداول والتخزين المتعلق بالحساب، وتأكد من إجراءات حذف البيانات المطلوبة.
   حذف مستخدم Auth قد يؤدي إلى حذف الصفوف المرتبطة ON DELETE CASCADE، بما فيها طلب الحذف نفسه.
5) تغيير حالة الطلب إلى resolved لا يحذف أي بيانات ولا يرسل أي إشعار. لا تستخدمه بدل تنفيذ الإجراء الفعلي.

اختبار وتوثيق:
- تم فحص صياغة TypeScript/TSX وسلامة مراجع الملفات والأوامر الأساسية للـSQL محليًا.
- لم يتم تنفيذ SQL على Supabase الحقيقي، ولم يتم تشغيل Cloudflare Build أو اختبار RLS بحسابين حقيقيين.
